ส่วนที่ 1: เครื่องมือและเทคโนโลยีที่ใช้ในโปรเจกต์ (Tech Stack & Tools)

โปรเจกต์นี้ได้รับการพัฒนาบนสถาปัตยกรรม Modern Full-Stack Web Application โดยเลือกใช้เครื่องมือที่ทันสมัยและเป็นมาตรฐานสากล เพื่อรองรับประสิทธิภาพสูงสุด (High Performance), ความปลอดภัยระดับสูง (Enterprise-Grade Security) และความเสถียรในการทำงานระยะยาว

หมวดหมู่ เทคโนโลยี / ไลบรารี บทบาทหน้าที่ในระบบ
Core Framework Next.js 16.4.3 (App Router) โครงสร้างหลักแบบ Full-Stack รองรับ Server Components, Server Actions และระบบ Routing แบบ Dynamic
Bundler & Compiler Turbopack (Rust-based) ระบบคอมไพล์โค้ดความเร็วสูง รองรับ Fast Refresh และ Optimized Production Build
UI Library & State React 19.3.0 การจัดการคอมโพเนนต์และการเรนเดอร์แบบ Concurrent, useTransition, Action States
Type System TypeScript 5 ตรวจสอบความถูกต้องของประเภทข้อมูลแบบ Strict Type Checking ป้องกัน Runtime Error 100%
ORM & Database Client Prisma ORM 6.19.3 Object-Relational Mapping จัดการโครงสร้างตาราง, Migrations, Type-safe Query และ Parameterized Queries
Cloud Database PostgreSQL on Supabase ฐานข้อมูลเชิงสัมพันธ์บน Cloud (Region Tokyo: aws-0-ap-northeast-1) พร้อม Connection Pooler (PgBouncer พอร์ต 6543)
Styling & Design System Tailwind CSS v4 Utility-First CSS Engine ยุคใหม่ ธีม Dark Violet & Deep Black Aesthetic (#0c0a18) สอดคล้องกับ SRD
Iconography Lucide React (1.62.0) ชุดไอคอนแบบ SVG คุณภาพสูง สะอาดตาและประหยัด Bandwidth
Security & Auth Custom RBAC + Edge Proxy ระบบจำแนกสิทธิ์ 4 ระดับ (Unauthenticated, Tenant, Staff, Admin) พร้อม Server Action Guards
Hosting & CI/CD Vercel Cloud Platform โฮสติ้ง Production เชื่อมต่อ GitHub Pipeline (Auto-Deploy ทุกครั้งที่มีการ Push โค้ด)
Containerization Docker & Docker Compose รองรับการรัน Environment แบบจำลองตู้คอนเทนเนอร์ (Dockerfile.dev, docker-compose.yml)

สถาปัตยกรรมความปลอดภัยและการปกป้องข้อมูล (Security & PDPA Architecture)

  • HTTP Security Headers: ติดตั้ง Header ผ่าน next.config.ts เช่น X-Frame-Options: DENY (ป้องกัน Clickjacking), X-Content-Type-Options: nosniff, Referrer-Policy, HSTS และ Permissions-Policy
  • Defense-in-Depth Authorization: เสริมการตรวจสิทธิ์ซ้ำระดับเซิร์ฟเวอร์ที่ src/lib/auth-guard.ts ในทุก Server Action ป้องกันช่องโหว่ OWASP A01: Broken Access Control
  • Anti-Brute-Force Delay: หน่วงเวลา 400ms เมื่อมีการล็อกอินผิดพลาดเพื่อป้องกันการโจมตีแบบสุ่มรหัสผ่านด้วย Bot
  • PDPA Data Masking: ซ่อนหมายเลขบัตรประชาชน 13 หลักของผู้เช่าในหน้าจอทั่วไปด้วยฟังก์ชัน maskThaiId() (แสดงผลเป็น •••••••••1234)

2.1 การใช้งานสำหรับผู้เช่า (Tenant Portal)

  1. การเข้าสู่ระบบผู้เช่า:

    ไปที่หน้าแรกของระบบ (/) เลือกแท็บ "สำหรับผู้เช่า (Tenant)" กรอกข้อมูล 3 ส่วนเพื่อความปลอดภัยสูงสุด:

    • หมายเลขห้องพัก (เช่น 101 หรือ 201)
    • เบอร์โทรศัพท์ที่ลงทะเบียนในสัญญาเช่า (เช่น 0812345678)
    • เลขท้าย 4 หลักของบัตรประชาชน (เพื่อป้องกันบุคคลอื่นแอบดูบิล)
  2. หน้าแรกพอร์ทัลผู้เช่า (/me):

    แสดงการ์ดยอดค้างชำระรวม, ข้อมูลสัญญาเช่าปัจจุบัน, ปุ่มลัดชำระเงิน, และรายการแจ้งซ่อมบำรุงล่าสุด

  3. การตรวจสอบบิลและประวัติการชำระ (/me/invoices):

    สามารถคลิกดูรายละเอียดของใบแจ้งหนี้แต่ละเดือน ดูหน่วยน้ำ-ไฟที่ใช้ ยอดรวมที่ต้องชำระ บัญชีรับเงินของหอพัก และกดปุ่มพิมพ์ใบแจ้งหนี้หรือใบเสร็จรับเงิน

  4. การแจ้งซ่อมแซมห้องพัก (/me/repairs/new):

    ผู้เช่าระบุหัวข้องานซ่อม, เลือกหมวดหมู่ (⚡ ไฟฟ้า, 🚿 ประปา, ❄️ แอร์, 🪑 เฟอร์นิเจอร์), เลือกระดับความเร่งด่วน, อธิบายอาการ, และแนบลิงก์รูปถ่าย จากนั้นกดส่งเรื่อง

2.2 การใช้งานสำหรับเจ้าหน้าที่และผู้ดูแลระบบ (Staff & Admin)

💡 การเข้าสู่ระบบ: เลือกแท็บ "ผู้ดูแล & เจ้าหน้าที่ (Admin)" กรอกอีเมลเจ้าหน้าที่ หรือคลิกปุ่ม Quick Demo เพื่อเข้าสู่ระบบในฐานะ Admin หรือ Staff ได้ทันที
  1. แดชบอร์ดภาพรวม (/dashboard):

    แสดงตัวชี้วัดหลัก 4 รายการ (จำนวนห้องทั้งหมด, อัตราการเข้าพัก %, รายได้รวมเดือนปัจจุบัน, ยอดค้างชำระรวม) พร้อมตารางผังห้องพัก Interactive Grid แสดงสีตามสถานะห้องแบบ Real-time

  2. การจัดการห้องพัก (/rooms):

    สามารถกดปุ่ม "+ เพิ่มห้องพักใหม่" หรือใช้เครื่องมือ "สร้างห้องพักแบบชุดทั้งชั้น (Batch Generator)" เพื่อสร้างห้องพักทีละหลายห้องได้ในคลิกเดียว (ตามกฎ BR-03 สถานะห้องใหม่จะเป็น ว่าง หรือ ปรับปรุง เท่านั้น)

  3. ทะเบียนผู้เช่า (/tenants):

    บันทึกประวัติผู้เช่าใหม่ ตรวจสอบเลขบัตรประชาชน 13 หลักด้วยสูตร Modulo 11 (กฎ BR-01) โดยในหน้ารายการข้อมูลเลขบัตรจะถูกปกปิด (Masking) ตามมาตรฐาน PDPA

  4. สัญญาเช่าห้องพัก (/contracts):
    • ทำสัญญาใหม่ (BR-02): เลือกห้องพักและผู้เช่า กำหนดค่าเช่า ค่ามัดจำ ค่าน้ำ-ไฟ และวันครบกำหนด เมื่อบันทึกห้องจะเปลี่ยนเป็น occupied อัตโนมัติ
    • สิ้นสุดสัญญาและคืนเงินมัดจำ (BR-10): ระบบจะคำนวณเงินมัดจำหักกลบลบหนี้ค้างชำระและค่าเสียหายให้อัตโนมัติ พร้อมคืนสถานะห้องเป็น vacant
    • ต่ออายุสัญญา (Renew): สิ้นสุดสัญญาเดิมและสร้างสัญญาฉบับใหม่ต่อเนื่องทันที
  5. การบันทึกมิเตอร์น้ำ-ไฟ (/meters):

    สามารถบันทึกได้ทั้งแบบรายห้องและแบบทั้งตาราง (Batch Save) ตามกฎ BR-04 ระบบจะตรวจสอบว่าเลขมิเตอร์ครั้งปัจจุบันต้องไม่ต่ำกว่าครั้งก่อนหน้า และหากห้องใดถูกนำไปออกบิลแล้ว ตารางจะล็อกเพื่อป้องกันการแก้ไข

  6. ระบบใบแจ้งหนี้รายเดือน (/invoices):

    กดปุ่ม "+ ออกใบแจ้งหนี้" เพื่อคำนวณค่าน้ำ-ไฟตามหน่วยการใช้งานจริง พร้อมปัดเศษทศนิยมตามกฎ BR-05 (Decimal Half-Up) และบังคับกฎ 1 ห้อง 1 บิลต่อเดือน (BR-06)

  7. การรับชำระเงินและใบเสร็จ (/payments):

    บันทึกการรับชำระเงินสดหรือโอนเงินผ่านธนาคาร ระบบจะออกเลขที่ใบเสร็จรับเงิน RCP-YYYYMM-XXXX อัตโนมัติ (BR-11) และหากบันทึกผิด กฎ BR-12 จะไม่อนุญาตให้ลบแต่ให้ทำรายการยกเลิกแบบ Void พร้อมระบุเหตุผล

  8. การจัดการงานแจ้งซ่อมบำรุง (/repairs):

    ระบบควบคุม Workflow 3 ขั้นตอน: รอดำเนินการ (open) → กำลังดำเนินการ (in_progress) → เสร็จสิ้น (done) พร้อมระบุค่าใช้จ่ายและบันทึกผลการซ่อม (การย้อนสถานะจาก done กลับเป็น in_progress อนุญาตเฉพาะ Admin ตามกฎ SRD 4.22)

  9. รายงานการเงินและสถิติ (/reports/*):

    ดูรายงานสรุป 4 มิติ (รายงานรายรับ, อัตราเข้าพัก, หนี้ค้างชำระ, สถิติงานซ่อม) พร้อมปุ่ม Export CSV เพื่อดาวน์โหลดข้อมูลไปใช้งานต่อใน Excel

2.3 สิทธิ์พิเศษเฉพาะผู้ดูแลระบบสูงสุด (Admin Features - /admin/users)

  • เพิ่ม/แก้ไข/ระงับบัญชีผู้ใช้งาน: เพิ่มชื่อ อีเมล เบอร์โทร และกำหนดบทบาท Staff หรือ Admin
  • ตั้งค่าส่วนกลางของหอพัก: แก้ไขชื่อหอพัก, เลขที่บัญชีธนาคาร/พร้อมเพย์, อัตราค่าน้ำ-ไฟเริ่มต้น, และวันครบกำหนดชำระเงิน

ส่วนที่ 3: แผนและวิธีการทดสอบระบบ (Testing Guide & Test Cases)

🎯 สคริปต์ทดสอบเร่งด่วน 5 นาทีสำหรับอาจารย์ (5-Minute Quick Test Script):
  1. นาทีที่ 1: เปิดหน้าแรก (/) กดปุ่ม Quick Tenant เข้าสู่พอร์ทัลผู้เช่าห้อง 101 ตรวจดูบิลและทดลองส่งแจ้งซ่อมบำรุง
  2. นาทีที่ 2: กดออกจากระบบ ล็อกอินด้วย Staff Quick Demo สังเกตป้ายยศ STAFF 🧑‍💼 บน Navbar และสังเกตเมนู จัดการผู้ใช้และสิทธิ์ จะถูกล็อก 🔒
  3. นาทีที่ 3: ไปที่หน้า /meters ทดสอบจดมิเตอร์น้ำไฟ และไปที่ /invoices กดออกใบแจ้งหนี้อัตโนมัติ
  4. นาทีที่ 4: ไปที่หน้า /payments บันทึกรับชำระเงินและดูใบเสร็จรับเงินเลขที่ RCP
  5. นาทีที่ 5: กดออกจากระบบ ล็อกอินด้วย Admin Quick Demo สังเกตป้ายยศ ADMIN 🛡️ และเข้าหน้า /admin/users เพื่อจัดการผู้ใช้

ตารางกรณีทดสอบระบบครบวงจร (System Test Cases Specification)

รหัสทดสอบ ฟังก์ชันที่ทดสอบ ขั้นตอนการทดสอบ (Steps) ผลลัพธ์ที่คาดหวัง (Expected Result)
TC-01 การล็อกอินผู้เช่าแบบปลอดภัย 3 ชั้น กรอกเลขห้อง 101, เบอร์โทร, และเลขท้ายบัตร ปชช. 4 หลัก เข้าสู่หน้า /me ของห้อง 101 ได้ถูกต้อง หากกรอกเลขบัตรผิดจะถูกปฏิเสธพร้อมหน่วงเวลา 400ms
TC-02 การป้องกันสิทธิ์เส้นทาง (RBAC) ขณะเป็นผู้เช่า ให้ลองพิมพ์ URL /dashboard หรือ /rooms ระบบ Proxy สกัดกั้นทันที และ Redirect ผู้ใช้กลับมายังหน้า /me
TC-03 การจำกัดสิทธิ์ของ Staff ล็อกอินเป็น Staff แล้วพิมพ์ URL /admin/users หรือคลิกเมนูผู้ใช้ ระบบบล็อกการเข้าถึงและดีดกลับมาที่ /dashboard ตามกฎ RBAC
TC-04 การตรวจสอบเลขบัตร ปชช. (BR-01) ไปหน้า /tenants/new กรอกเลขบัตร ปชช. ที่ Checksum ผิด ระบบแจ้งเตือน "เลขบัตรประชาชนไม่ถูกต้องตามสูตร Modulo 11"
TC-05 การทำสัญญาเช่าห้องพัก (BR-02, BR-03) ทำสัญญาเช่าห้องว่างใหม่ที่ /contracts/new บันทึกสัญญาสำเร็จ และสถานะห้องพักในผังเปลี่ยนเป็น occupied ทันที
TC-06 การตรวจสอบเลขมิเตอร์ (BR-04) จดมิเตอร์ที่ /meters โดยใส่เลขปัจจุบันต่ำกว่าเลขเดิม ระบบแจ้งเตือนข้อผิดพลาดตามกฎ BR-04 ไม่อนุญาตให้บันทึก
TC-07 การออกบิลและปัดเศษทศนิยม (BR-05, BR-06) ออกใบแจ้งหนี้แบบชุดที่ /invoices ระบบคำนวณค่าน้ำ-ไฟตามสูตร ปัดเศษแบบ Half-Up และป้องกันการออกบิลซ้ำในเดือนเดียวกัน
TC-08 การคิดค่าปรับชำระล่าช้า (BR-09) กดคิดค่าปรับล่าช้าในใบแจ้งหนี้ที่เลยวันครบกำหนด บวกค่าปรับตามสัญญาสำเร็จ และปุ่มจะถูกปิดเพื่อป้องกันการคิดค่าปรับซ้ำเกิน 1 ครั้ง
TC-09 การรับชำระเงินและออกใบเสร็จ (BR-08, BR-11) บันทึกการชำระเงินที่ /payments ออกใบเสร็จรับเงินเลขที่ RCP-YYYYMM-XXXX ต่อเนื่อง และสถานะบิลเปลี่ยนเป็น paid
TC-10 การยกเลิกใบเสร็จรับเงิน (BR-12) กดยกเลิกใบเสร็จรับเงินในหน้ารายละเอียดการชำระเงิน ระบบเปลี่ยนสถานะเป็น voided บันทึกเหตุผล และคำนวณยอดค้างของบิลกลับมา
TC-11 เวิร์กโฟลว์งานแจ้งซ่อมบำรุง (SRD 4.22) เปลี่ยนสถานะงานซ่อมจาก open → in_progress → done ต้องผ่าน in_progress ก่อนเสมอ และการย้อนสถานะจาก done กลับทำได้เฉพาะ Admin
TC-12 การสิ้นสุดสัญญาและคืนเงินมัดจำ (BR-10) กดยุติสัญญาห้องพักที่ /contracts/[id] ระบุค่าเสียหาย คำนวณเงินมัดจำหักยอดค้างและค่าเสียหายอัตโนมัติ และคืนสถานะห้องพักกลับเป็น vacant
